# Data requirement matrix

The UI derives this matrix from backend readiness. It does not maintain a second scientific rule set.

| Item | S1 | S2 | User state |
|---|---|---|---|
| Analysis units | Required | Required | Provided / Missing |
| Candidate matrix | Required | Required | Provided / Review required |
| Current pattern | Required | Required | Provided / Review required |
| Annual water and validated water domains | Readiness-defined | Readiness-defined, with additional S2 needs | Provided / Review required |
| Economics, crop parameters, phenology | Readiness-defined | Readiness-defined | Provided / Review required |
| Geometry | Optional | Optional | Provided / Missing; analysis may continue |

Each item shows a short Turkish explanation and retains its technical connection state in expandable details. A scenario that is not ready is disabled and its backend blocking reasons remain visible.
