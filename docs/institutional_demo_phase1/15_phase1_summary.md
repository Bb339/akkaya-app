# Institutional demo integration Phase 1 summary

Phase 1 connects the existing project import contracts to the accepted scientific engine through explicit project-scoped adapters. `REFERENCE_DEMO` retains the frozen Akkaya path and identifies its results as reference/demo output. `VERIFIED_INSTITUTIONAL` resolves only active, confirmed, current, planning-year and scope-compatible datasets; a critical gap blocks preview and execution without a reference fallback.

The verified path covers water, economics, crop water parameters, phenology, candidates and the current pattern. Readiness and dry-run responses show the selected dataset versions, authority, coverage, warnings and blockers before execution. Each completed run stores the resolved inputs and their provenance, engine commit, algorithm configuration, readiness snapshot and result classification. Replacing a confirmed upstream input preserves the old run and marks the project for reanalysis.

The end-to-end acceptance fixture is explicitly named `SYNTHETIC_INSTITUTIONAL_TEST_PROJECT` and carries `SYNTHETIC` / `NOT_OFFICIAL` metadata. It proves create, upload, mapping, validation, preview, confirmation, readiness, dry-run, scientific execution, result and provenance behavior. A controlled water replacement changes the pinned evidence and resulting output while leaving the earlier run immutable.

The accepted scientific engine and frozen Akkaya data are byte-identical to the robustness completion baseline. No publication artifact, deployment, remote push or Phase 1 completion tag was produced. The known inherited S2 feasibility expectation remains backlog and is reported without claiming that all tests pass.
